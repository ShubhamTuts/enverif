# Enverif 1.4 Production Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Enverif 1.4.0 as a backward-compatible, zero-data-loss hardening release that combines the existing chat/agent orchestration fixes with durable live run UX, Action Center approvals, capability-driven mail (including optional IMAP on SMTP), safe plugin/connection removal, tenant/RBAC security, exactly-once external actions and release reliability.

**Architecture:** Preserve the current Laravel monolith/shared-hosting architecture and existing persisted primitives. Chat remains a projection over persisted runs/steps/approvals, connectors expose normalized capabilities instead of chat-level brand logic, and external writes pass through a durable execution/idempotency boundary. Changes are incremental migrations and focused services rather than a rewrite.

**Tech Stack:** PHP 8.3+, Laravel 13, MySQL, Redis or database queue, Blade, vanilla JavaScript, Vite, Symfony Mailer, PHP IMAP extension when IMAP is enabled, PHPUnit, standalone verifier scripts, GitHub Actions.

## Global Constraints

- Target version: `1.4.0`.
- Upgrade from existing `1.3.x` data in place; no destructive migration or data loss.
- Shared hosting remains supported without Redis/SSH.
- Chat/orchestrator code must not hardcode Gmail, Outlook, SMTP, IMAP, GitHub or future integration brands.
- External sends/writes remain approval-first unless workspace/agent policy explicitly permits autonomy.
- Built-in plugins are not physically uninstallable; external plugins may be safely disabled/uninstalled.
- Important run/approval UI state must be reconstructed from persisted server records after refresh.
- Existing visual language remains; reusable global CSS/JS primitives are preferred over page-specific patches.
- Secrets are encrypted at rest, redacted in UI/logs, and never silently forwarded to a newly changed endpoint.
- Source/public frontend assets must remain synchronized.
