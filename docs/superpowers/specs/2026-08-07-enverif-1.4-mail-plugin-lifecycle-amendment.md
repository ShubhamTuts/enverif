# Enverif 1.4 Mail + Plugin Lifecycle Amendment

Date: 2026-08-07
Target: Enverif 1.4.0
Parent spec: `2026-08-07-enverif-1.4-production-hardening-design.md`
Status: Approved with parent spec

## SMTP + IMAP capability expansion

The existing SMTP connector remains backward compatible for current installations and existing encrypted SMTP configuration. It is extended into a generic mail-server connection that can optionally configure IMAP alongside SMTP.

### Capability contract

Capabilities are discovered from the configured transport rather than from vendor-specific conditionals in chat/orchestration.

- SMTP configured: `mail.send`
- SMTP + sender metadata configured: `mail.draft`, `mail.send` where supported by Enverif's local drafting behavior
- IMAP configured: `mail.search`, `mail.thread.read`, `mail.message.read`, `mail.receive`
- IMAP + SMTP configured: the union of read and send capabilities, including `mail.reply` when a message can be replied to using the configured SMTP sender identity

Gmail and Outlook expose the same normalized capabilities through their own drivers. Chat and the agent runtime may select any connector that satisfies the requested capability; they must not branch on Gmail, Outlook, SMTP or IMAP names.

### IMAP configuration

Add optional encrypted IMAP credentials/configuration to the existing SMTP connection form/manifest without invalidating SMTP-only connections:

- host
- port (default 993)
- encryption (`ssl`, `tls`, `none` where explicitly allowed)
- username
- password
- mailbox/folder default (`INBOX`)
- connection timeout
- certificate verification enabled by default

The connection test reports SMTP and IMAP health separately. Enverif must never expose stored credentials in diagnostics or chat traces.

### IMAP actions

The connector provides bounded, safe read operations at minimum:

- search messages using normalized filters (query/from/to/subject/date/unread/limit)
- list recent messages
- read a message
- read a thread/conversation where thread reconstruction is possible using `Message-ID`, `In-Reply-To`, `References` and subject participants
- receive/check for new mail
- obtain reply metadata needed for SMTP reply (`Message-ID`, reply-to/from, subject)

Mailbox results are normalized into the same Enverif mail envelope/message DTO shape used by Gmail and Outlook so agents reason over one schema.

Read operations are bounded by item count/body bytes and return truncation metadata when limits are exceeded.

### Reply behavior

Reply is capability-driven: Enverif reads the target message via any connector that provides `mail.message.read`/`mail.thread.read`, then sends through a connector that provides `mail.send`. For the combined SMTP+IMAP connection this can be the same connection. Thread headers are preserved when SMTP supports the reply send.

All actual sends/replies remain external writes and therefore follow approval/idempotency policy.

## Added plugin and connection removal

Externally added plugins must expose an uninstall/remove action in the UI when they are removable. Built-in plugins are not physically uninstallable; they may be disabled when applicable.

### Lifecycle separation

- Disable connection: reversible; credentials/configuration remain.
- Disconnect connection: revoke/remove credentials where supported; preserve historical run/audit references and non-secret configuration.
- Delete connection: remove the configured connection after dependency review/confirmation.
- Disable external plugin: stop new use while keeping package and historical metadata.
- Uninstall external plugin: remove the external plugin package/registration only after dependency checks.

### Dependency handling

Before deleting a connection or uninstalling a plugin, Enverif calculates and displays dependencies including agents, workflows, schedules, campaigns and other configuration references.

The default behavior is to block destructive removal while active dependencies exist. The user must first detach/migrate/delete those dependencies, or use an explicitly supported safe cascade that is shown before confirmation. Historical `AgentRun`, `WorkflowRun`, `AuditEvent`, chat and approval records remain readable and must not be destroyed merely because a connector/plugin is removed.

### Security and UX

- owner/admin capability required to disconnect/delete connections or uninstall external plugins
- confirmation modal/card uses the global destructive-action component
- destructive action is never a one-click GET link
- audit entry records actor, plugin/connection identity, dependency summary and result
- external plugin file deletion validates the resolved path is inside `plugins/external/` and cannot traverse elsewhere
- uninstall does not execute arbitrary plugin-provided uninstall PHP in 1.4.0; Enverif owns the package deletion lifecycle

## Acceptance

The amendment is complete when an existing SMTP-only connection continues to send without migration breakage; adding IMAP immediately exposes read/search/receive capabilities to agents without chat changes; Gmail/Outlook/SMTP+IMAP all use normalized mail capability/data contracts; and an administrator can safely disconnect/delete configured connections and uninstall dependency-free external plugins through confirmed, audited UI actions.
