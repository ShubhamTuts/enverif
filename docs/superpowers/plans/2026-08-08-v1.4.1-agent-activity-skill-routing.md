# Enverif v1.4.1 Agent Activity + Skill/Plugin Routing Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship Enverif v1.4.1 with shared-hosting Skill/Plugin routes working for admins, a global top-bar Agent activity experience with correct dark mode and real agent avatars, no large inline Live Activity block in chat, and no regressions to durable runtime/approval behavior.

**Architecture:** Keep Laravel's existing persisted runtime (`AgentRun`, child runs, steps, approvals) as the only source of truth. Fix Apache routing at the shared-host front door, extend the existing `RuntimeFeedController` and `RunProjection` with presentation-safe metadata, and make `runtime-ui.js` a global drawer controller that consumes the lightweight feed plus on-demand run projection rather than maintaining a second state system or a second high-frequency chat poll. Preserve current capability-driven connectors/skills/MCP snapshots and approval policy; the UI must remain generic and must not branch on agent or integration brands.

**Tech Stack:** Laravel 13 / PHP 8.3+, Blade, vanilla JavaScript, CSS custom properties, Apache mod_rewrite, PHPUnit/Laravel feature tests, existing standalone/release verification scripts, GitHub Actions.

## Task 4: Make the Agent activity drawer complete, generic, and efficiently live

**Files:**
- Modify: `resources/js/runtime-ui.js`
- Modify: `public/assets/runtime-ui.js`
- Modify if needed: `app/Http/Controllers/ChatActivityController.php`
- Modify if needed: `routes/web.php` only if the existing projection endpoint cannot safely support global inspection
- Extend: runtime JS/controller tests from Task 3

### Step 1: Write RED behavior assertions

Tests/static assertions should prove:
- drawer heading is **Agent activity**, not `Run activity`;
- primary and child agent rows can render different avatar URLs;
- generic tool labels/status/risk/timestamps are rendered from projection fields;
- approvals expose Approve/Deny actions in context;
- no connector/agent brand names are hardcoded in runtime JS;
- no automatic duplicate 900 ms `/activity` poll starts merely because a chat page is open.

Where JS DOM behavior cannot be fully exercised by existing tooling, add focused source-contract assertions plus Laravel HTTP tests and keep browser behavior covered by the existing CI frontend smoke path.

### Step 2: Change drawer rendering to use real avatars

Render `<img>` when `agent_avatar_url` is present. Use escaped initial/Enverif fallback only when absent or image fails. Add `alt` text based on generic agent name.

Each child run must use its own avatar metadata.

### Step 3: Add global run selection

When the drawer opens outside chat:
- show active/recent runtime-feed items first;
- selecting one fetches its durable projection without navigating away;
- use existing run/thread URLs only as secondary deep links.

When opened from a chat, default to that chat's latest run tree.

Prefer extending/reusing the existing projection endpoint. If a global route is necessary, create one generic authenticated controller action keyed by run id and enforce workspace/user visibility; do not duplicate `RunProjection` logic.

### Step 4: Make detailed polling on-demand

Replace unconditional chat `/activity` polling with:
- global lightweight feed polling at existing bounded cadence;
- one detailed projection fetch when the drawer opens/selects a run;
- re-fetch detailed projection only while the drawer is open **and** selected run tree has a non-terminal run;
- slower/backed-off polling while `document.hidden`;
- stop detailed timer when drawer closes or selection becomes terminal.

Do not let the browser advance queues or become the runtime worker.

### Step 5: Preserve current chat-status event integration

If current `app.js` emits live status/projection data for the active chat, consume that event to refresh the selected drawer state rather than introducing another transport. Preserve the earlier MutationObserver freeze fix; do not observe/mutate the same subtree recursively.

### Step 6: Preserve approval lifecycle

Approval button submission must:
- POST CSRF-protected decision to existing `approvals.decide`;
- disable card controls while request is pending;
- tolerate already-decided 409 responses;
- refresh the selected projection and global counts;
- never infer approval completion before durable server response.

## Completion criteria

The work is complete only when all of the following are simultaneously true:

- Admin/owner Skill create/install and plugin lifecycle routes are not intercepted by Apache.
- Member authorization remains restricted by Laravel capability middleware.
- Private application source paths remain unavailable from shared hosting.
- The large inline `Live activity` block is gone from chat.
- A global top-bar **Agent activity** control works on chat and non-chat authenticated pages.
- Drawer uses correct dark/light Enverif tokens and no white fallback surface in dark mode.
- Drawer can inspect primary/sub-agent run trees with real per-agent avatars, generic tools/connectors/MCP steps, statuses, timestamps and approvals.
- Activity UI contains no agent/vendor-specific execution branching.
- Detailed activity polling is on-demand and bounded; the browser is an observer, not a queue worker.
- Source/public runtime JS and CSS are byte-identical.
- Exact versioned branch candidate passes full CI.
- Exact merged main SHA passes full CI.
- `v1.4.1` tag/release points to that verified commit and release artifacts pass verification.
